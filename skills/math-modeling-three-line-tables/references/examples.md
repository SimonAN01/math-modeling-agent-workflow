## 1. 压缩表内散文

不宜：

| 处理步骤 | 具体说明 |
|---|---|
| 缺失数据处理 | 对少量位于序列内部的连续缺失点，本文采用线性插值的方法进行补全处理。 |
| 异常数据筛查 | 本文根据预先定义的异常判定规则，对观测中可能异常的样本进行识别并标记。 |
| 尺度处理 | 为使指标能够在相同尺度下参与计算，按照既定设置对各指标进行标准化。 |

可改：

| 处理对象 | 操作 | 关键条件 |
|---|---|---|
| 序列内部短缺口 | 线性插值 | 两端观测有效 |
| 可疑观测 | 标记与复核 | 按预定义规则 |
| 待比较指标 | 标准化 | 参数来源另述 |

表注补充短缺口定义和具体规则的真实出处。参数来源需要据实际任务说明，不能泛指“全数据统计”。注意：若原文没有确认边界条件或参数来源，新增的内容应标为待核验，而不能伪装成已实施操作。

如果这些操作无比较或复现需求，直接写成一个紧凑段落也可以，不必保留表格形式。

## 4. 算法不是三列散文

不宜：

| 步骤 | 名称 | 说明 |
|---|---|---|
| 1 | 开始处理 | 首先根据已有条件开展数据处理，并进行必要的计算。 |
| 2 | 进行求解 | 然后使用相关算法进行不断迭代，使结果逐渐变好。 |
| 3 | 结束输出 | 最后得到最优结果并证明算法的有效性。 |

这不能说明变量、更新、判断或终止，换成三线边框也不是有效的伪代码。

### 一个完整的有限候选筛选示例

目标：在给定有限候选集合中，筛选目标值最小的可行方案。此例只是算法表表达方式，不适用于所有建模问题。

输入：有限候选集C，可行性判定Feasible，实值目标函数f（越小越优）。
输出：选中的可行候选x_best，或“无可行候选”状态。

```text
1  x_best ← 空；b ← +∞；found ← false
2  for 每个候选 x ∈ C do
3      if Feasible(x) then
4          v ← f(x)
5          if v < b then
6              x_best ← x；b ← v；found ← true
7          end if
8      end if
9  end for
10 if not found then
11     return “无可行候选”
12 end if
13 return x_best
```

算法含义：先筛可行性，再更新目标值最小的已评估候选；found标志区分未发现可行解与合法的空结构候选。目标函数在可行候选上需有定义且为有限实数；相同目标值保留遍历中先遇到的候选。由于候选集有限，遍历结束即终止；不强加收敛阈值或迭代次数。

若每次可行性检查和目标计算成本分别为T_g与T_f，最坏时间可写为O(|C|(T_g+T_f))。这里的最优只针对给定候选集合中的可行元素，不意味着原始连续或组合空间的全局最优。

前文：候选方案的筛选过程见算法X。

后文：算法将可行性判断置于目标比较之前，并保留目标值最小的已评估候选；具体选中方案及其数值放入结果表。

## 5. 非迭代与迭代算法如何分别表达

直接计算／求解器调用：列输入、数据到模型映射、关键调用、状态检查和输出；没有循环就不写While。

迭代方法：按真实算法列初值、一次更新、条件分支、停止或预算上限、返回内容；子程序需定义。达到预算不等于达到数学收敛条件。

统计预测：训练、参数选择与测试的关系需真实，不能为了简单把测试数据送入训练。若涉及预处理参数估计，说明参数在哪个数据范围学习并如何用于测试。

以上是核验问题，不是要求每种算法强制含有同样阶段。
